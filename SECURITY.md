# Security Policy

## Supported Versions

As this repository contains educational material, sample code snippets, and interview questions, security updates primarily address security recommendations in code examples, dependencies used in scripts/workflows, or documentation errata.

| Type | Status |
|---|---|
| Main Branch Content | :white_check_mark: Supported |
| Archived Releases | :x: Unsupported |

## Reporting a Vulnerability

If you discover any security vulnerability in code examples (e.g., SQL injection risks presented without appropriate disclaimers, insecure deserialization, unsafe authentication snippets, or hardcoded sensitive defaults), or in the automated GitHub Actions pipelines:

1. **Do not open a public issue.**
2. Send an email to the repository maintainer or use the GitHub Private Vulnerability Reporting feature if enabled.
3. Provide detailed steps to reproduce the issue, the impacted file and lines, and suggested remediation.
4. Maintainers will review the submission, draft a fix, and acknowledge the report in the changelog.

We appreciate responsible security disclosures that keep engineering interview candidates learning production-safe patterns.
